# tmux_helper — облачные помощники через ollama TUI в tmux

Облачная модель работает **быстро и без загрузки** (в отличие от локальных, где загрузка 3–4 мин). Запуск идёт не `ollama run`, а интерактивным TUI: открываем лаунчер, выбираем cloud-модель, попадаем в чат. Каждый помощник — отдельная tmux-сессия; **несколько сессий можно держать параллельно** для независимых задач (helper_1…, helper_2… и т.д.).

## Облачные модели
Целевые для запуска = те, что в списке TUI **БЕЗ подписи** под названием **И БЕЗ метки `(Upgrade required)`**. На момент записи:
- `gemma4:cloud`
- `gpt-oss:120b-cloud`
- `nemotron-3-super:cloud`

Правило выбора надёжнее заголовка списка: в фильтре `cloud` ищи именно строки **без второй строки-описания** и без `(Upgrade required)` рядом. Если список обновился (появились новые названия) — ориентироваться на это правило, а не на жёсткий список выше.

## Шаг 0: проверка существующих сессий
Сначала всегда посмотри, что уже запущено (если ранее в этом же диалоге ещё не делал):
```bash
tmux ls | grep -E "helper_[0-9]+" || echo "нет helper-сессий"
```
- Сессия под нужную задачу уже жива → просто отправляй в неё ввод (`send-keys`), **не создавай новую**.
- Нет → шаг 1.

## Шаг 1: создание сессии
Имя формата `helper_<номер>_<текущая дата DDMMYYYY>` (дата = `$(date +%d%m%Y)`). Номера 1,2,3… по порядку в рамках задачи.
```bash
tmux new-session -d -s helper_1_06092026     # номер подставь свой, дату — актуальную
sleep 1; tmux ls | grep helper               # убедиться что сессия появилась
```

## Шаг 2: запуск TUI и выбор cloud-модели (клавишами)
Все действия отдельными командами `tmux send-keys -t <сессия>`, **после каждого GUI-действия проверь экран** `capture-pane` (вставка текста/выбор — проверяешь; мигающий курсор может не попасть на снимок).

### Чтение экрана: единый шаблон ОБЯЗАТЕЛЕН (защита от пустого кадра)
После старта TUI / очистки экрана первый `capture-pane` иногда возвращает **пустоту** (кадр во время перерисовки). Поэтому экран ВСЕГДА читаешь этим шаблоном (retry до непустого, максимум 5 попыток) — без отдельных «а вдруг пустой» мыслей:
```bash
S=helper_1_06092026
for i in $(seq 1 5); do OUT=$(tmux capture-pane -t $S -p | grep -v '^[[:space:]]*$'); [ -n "$OUT" ] && break; sleep 1; done
echo "--- кадр $i ---"; echo "$OUT"
```
Если даже после 5 попыток пусто — реально что-то не так, тогда думать.

Каждый шаг = одна команда bash: `tmux send-keys …` + сразу шаблон чтения экрана (КАДР). Не вставляй голый capture-pane.

```bash
S=helper_1_06092026   # имя сессии из шага 1
# КАДР = стандартный шаблон чтения (retry до непустого), см. выше
КАДР() { for i in $(seq 1 5); do OUT=$(tmux capture-pane -t $S -p | grep -v '^[[:space:]]*$'); [ -n "$OUT" ] && break; sleep 1; done; echo "--- кадр ---"; echo "$OUT"; }

# 2.1 ollama + Enter → лаунчер (меню "Chat, Code, & Work")
tmux send-keys -t $S "ollama"; sleep 1; tmux send-keys -t $S C-m; КАДР

# 2.2 стрелка вправо → список/выбор моделей (configure)
tmux send-keys -t $S Right; sleep 1; КАДР

# 2.3 фильтр "cloud" — остаются только облачные модели, курсор сверху
tmux send-keys -t $S cloud; sleep 1; КАДР

# 2.4 после фильтра «cloud» ВСЕГДА сразу PageDown (обязателен: курсор сверху, нужные
#     cloud-модели без подписи ниже). При необходимости докрути Up/Down.
#     Бери строку БЕЗ подписи снизу и БЕЗ "(Upgrade required)" (см. "Облачные модели").
tmux send-keys -t $S PageDown; sleep 1; КАДР

# 2.5 Enter → падаем в чат с выбранной моделью
tmux send-keys -t $S C-m; sleep 3; КАДР
```
Подтверждение готовности: внизу экрана `<имя-модели>   full access enabled`.

## Режим доступа (full vs review) — по умолчанию и когда менять
При входе в чат **по умолчанию включён `full access`** — модель действует автономно, без запросов подтверждения. Для типового использования это нормально: **если помощник нужен для поиска по интернету / раздумий БЕЗ задачи, взаимодействующей с системой (файлы, команды, GUI) → оставляй полный доступ**, он быстрее всего и не прерывает работу на одобрениях.

Если же модель будет **работать с твоей системой** (запускать Bash-команды, править файлы, клики в GUI), переведи её в **ограниченный режим `review mode`**: там каждое действие просит подтверждения — подтверждай вручную (выбор `1 Approve once`, либо `2 Always allow this command` для повторяющихся). Переключение:
```bash
tmux send-keys -t $S BTab     # Shift+Tab, циклически меняет режим; проверь строку статуса внизу
```
Не делай это «по умолчанию» — только когда задача реально трогает систему.

## Шаг 3: отправка задачи и чтение ответа
Текст строго через `-l` (литерально), Enter отдельной командой:
```bash
tmux send-keys -t $S -l -- "твоя задача"
КАДР    # проверить что текст в поле (шаблон из шага 2)
tmux send-keys -t $S C-m
```
Ответ модели тоже читаешь КАДР-ом: подожди ~3–5 сек после отправки, затем 1–2 раза `КАДР` с интервалом — когда кадр перестал меняться (ответ стабилен) или увидела маркер завершения ввода (пустое поле внизу), ответ готов. Либо спроси коротким токеном-сентинелом.

## Правила
1. Параллельные помощники = разные номера: `helper_1_<дата>`, `helper_2_<дата>`… Не путать сессиями оркестратора (`orchestrator-this-is-your-own-tmux-send-pictures-here-with-task`) — её убивать нельзя.
2. Ввод текста/клавиш — только через tmux send-keys; чтение экрана и детект готовности — всегда КАДР-шаблоном (retry до непустого), голый capture-pane не использовать.
3. После выполнения задачи сессию помощника можно убить: `tmux kill-session -t <сессия>` (по желанию).
