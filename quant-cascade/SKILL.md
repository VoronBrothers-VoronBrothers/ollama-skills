# Каскад квантов оркестратора

Оркестратор работает на базовом кванте **iq3_xxs** (`qwen3.8-orchestrator:latest`). Для сложных задач (тонкий код, длинные рассуждения) эскалирует на более тяжёлый квант и после решения ОБЯЗАТЕЛЬНО возвращается обратно.

## Скрипт
`/home/voron/Документы/VB-ollama/Скрипты_ИИ/quant_switch.sh`:
- `status` — текущий BOOT, модель TUI, существует ли в ollama
- `switch <iq3|iq4|q5|q8>` — полный переход: генерирует Modelfile (копия base + FROM нужного кванта), `ollama create`, console-скрипт, патчит `BOOT=` в restart_self.sh
- `restart` — self-restart через restart_self.sh (state.md ОБЯЗАТЕЛЕН, см. скилл save-session)

## Правила
1. **Эскалация** — при 2+ неудачных/затяжных попытках решить задачу на текущем кванте:
   `quant_switch.sh switch q5 && quant_switch.sh restart` (через save-session state.md обновить ДО restart).
2. **Деградация** — сложная задача решена → сразу возвращаться:
   `quant_switch.sh switch iq3 && quant_switch.sh restart`.
   Не оставлять тяжёлый квант надолго: дольше грузится, ест RAM/VRAM на idle.
3. **Иерархия**: iq3 (база) < iq4 < q5 < q8. Подниматься ступенью за раз; q8 — только если q5 мало.
4. Эскалация оркестратора НЕ заменяет делегирование: сначала пробовать ornith/qwen3-cod-NEXT, эскалация — последний инструмент перед сообщением о неудаче.
5. Проверить до/после: `quant_switch.sh status` — BOOT и модель должны совпадать с нужным квантом, статус «СУЩЕСТВУЕТ».
