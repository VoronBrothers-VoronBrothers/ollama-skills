# Helper — локальные помощники в tmux

## Модели для вызова
- `orchestrator-helper:latest` (12 GB)
- `cat:latest` (12 GB) (шуточная, изображает кошку)
- `ornith-1.5:35b` (22 GB)
- `qwen3-cod-NEXT-vb-no-promt:latest` (кодер, 51 GB, запуск ~3-4 минуты (терпимо), отвечает быстро (технология MoE))
- `gemma4:31b-cloud` — облачная

## Разовый вызов по API (по умолчанию, без tmux)
curl **блокируется до конца генерации** — готовность = команда завершилась, опроса/детекта вообще не нужно. Вывод — чистый JSON: размышления и ответ разделены полями `message.thinking` / `message.content`, мусора нет.
```bash
jq -n --rawfile q /tmp/question.txt '{model:"ornith-1.5:35b", stream:false, keep_alive:60, messages:[{role:"user", content:$q}]}' \
  | curl -s http://localhost:11434/api/chat -d @- > /tmp/ans.json
jq -r '.message.content' /tmp/ans.json     # thinking отдельно: .message.thinking
```
**Длинные вызовы (загрузка модели >40с) — curl запускать через nohup в фоне**, иначе команда оркестратора упадёт по таймауту: `nohup curl -s ... > /tmp/ans.json 2>/tmp/qwen_err.txt &`, потом подождать и прочитать файл (процесс curl исчез = ответ получен).

Мультитёрн = история целиком в массиве messages (раньше сообщения не отбрасывать). `keep_alive` — чтобы модель не выгрузилась между ходами.
Почему НЕ `ollama run ... > файл`: проверено — при редиректе ollama пишет в файл redraw-мусор (ANSI `[K`/частичные строки), а процессный детект даёт тот же API. Запасной вариант для мелких недумающих моделей: `ollama run cat:latest "задача"`.
Минусы API: нет стриминга (на длинных задачах прогресс не виден — если >2 минут команда не вернулась, проверь жив ли ollama: `curl -s localhost:11434/api/ps`).

## Интерактивный режим (tmux) — только для длинного мультитёрного чата
Имена сессий: `helper` или `tmux_helper`. Сессию оркестратора **orchestrator-this-is-your-own-tmux-send-pictures-here-with-task убивать ЗАПРЕЩЕНО** — и не путать её с helper.

### Шаг 0: предварительная проверка
```bash
tmux list-sessions | grep -E "helper|tmux_helper" || echo "нет helper-сессий"
```
- Сессия уже существует → помощник уже запущен, просто отправляй текст в её pane (шаг 2). Новый не создавай.
- Нет → создавай: `tmux new-session -d -s helper`, затем ввод командой запуска.

### Шаг 1: запуск
Текст и клавиши — отдельными командами (правило из скилла tmux):
```bash
tmux send-keys -t helper Enter
tmux send-keys -t helper -l -- "ollama run cat:latest"
tmux send-keys -t helper Enter
```

### Шаг 2: ожидание готовности и отправка задачи
Загрузка модели может занять минуты. Опрос цикла, не фиксированный sleep.
Поиск промпта ДОПУСТИТЕЛЬНЫЙ — без якоря `^` (перед `>>>` могут быть пробелы/курсор-символы):
```bash
for i in {1..180}; do
  SCREEN=$(tmux capture-pane -t helper -p | sed 's/\x1b\[[0-9;]*m//g' | col -b)
  if echo "$SCREEN" | grep -q "Send a message"; then break; fi
  sleep 2
done
```
Маркер готовности — `Send a message` где угодно в экране. Если маркер не появляется, но экран стабилен два снимка подряд (во время загрузки он меняется) — модель готова. В сомнении сделай selfshot и реши сам.
Текст задачи строго через `-l`, Enter отдельной командой. **Всегда заканчивай вопрос коротким уникальным словом `конец`** (≤20 символов, на одной строке — обёртка не перережет) — по нему в шаге чтения отрезается ответ.
**Токен-сентинел**: к вопросу добавляй просьбу «последней строкой каждого ответа напиши только токен 00000» (токен уникальный, редкий символы-цифры, не похож на слова темы; проси именно «последней строкой», не «в конце»). Токен — дополнение к детекту, НЕ гарантия: модель может забыть или впаять в текст.
```bash
tmux send-keys -t helper -l -- "задача... конец"
tmux send-keys -t helper Enter
```

### Шаг 3: ожидание ответа (детект завершения)
Готово = **стабильность экрана ИЛИ найден токен-сентинел** — любой из признаков. Спиннеры и строка `Thinking...` ненадёжны: после генерации они ОСТАЮТСЯ на экране/в истории и дают ложный «ещё думает» вечно; ждать их исчезновение — зациклиться. Промпт внизу тоже не жди: во время генерации его может быть нет или он с пробелами.
```bash
# Перед отправкой вопроса снять базовый снимок:
PRE=$(tmux capture-pane -t helper -p | sed '$d' | md5sum)
# Детект = контент уже отличался от PRE (убивает «мёртвый старт»)
# И серия из 3 одинаковых кадров подряд (~4-6с стабильности).
sed '$d' — срезает последнюю строку: там курсор/промпт, он мигает и даёт ложные md5-совпадения.
N=0; LAST=""; CHANGED=no
for i in {1..90}; do
  sleep 2
  H=$(tmux capture-pane -t helper -p | sed '$d' | md5sum)
  [ "$H" = "$PRE" ] || CHANGED=yes
  if [ "$LAST" = "$H" ]; then N=$((N+1)); else N=0; fi
  LAST=$H
  [ "$CHANGED" = yes -a $N -ge 3 ] && break   # менялось И стабилизировалось
done
```
**Запасной детект через pipe-pane** (если capture-pane не ловит изменения, например pane скроллится): до начала ответа включи `tmux pipe-pane -t helper:0.0 "cat >> /tmp/helper_stream.log"`, потом детектируй остановку по размеру файла — два замера с интервалом 2с: если `wc -c` не меняется → данные перестали поступать. Отключить после: `tmux pipe-pane -t helper:0.0`. Минусы: захват начинается только с момента вызова (история в файл не попадает), это polling размера файла — вариация варианта capture-pane, но уже на уровне байтов.

Остановилось подозрительно быстро (<5с от вопроса) — подожди ещё 3-4с и снимай снова (длинные паузы бывают).
**Токен-сентинел в детекте**: найден токен на последней содержательной строке = готовы, но сначала дождаться стабилизации контента (иначе срежем ответ в середине); код-блоки не в счёт. **Стабилен но токена нет** → подождать ещё ~10-20с; всё равно нет → считать готовым и при чтении проверить хвост на обрывок. **АВТОПЕРСПРОС «повтори последнюю строку» ЗАПРЕЩЁН** — модель добавит мусор, оживёт экран (петля).

### Чтение ответа (не переполнять контекст)
У моделей с видимым reasoning перед ответом катится длинный текст размышлений. Читать его ЗАПРЕЩЕНО: отрезай по последнему маркеру `...done thinking.`. У недумающих моделей такого маркера нет — режь после своего вопроса (по слову `конец`).
```bash
H=$(tmux capture-pane -t helper -p -S -500 | sed 's/\x1b\[[0-9;]*m//g' | col -b)
M=$(grep -n "done thinking" <<<"$H" | tail -1 | cut -d: -f1)   # ПОСЛЕДНИЙ маркер — модель может думать несколько раз
if [ -n "$M" ]; then
  TAIL=$((M+1))
else
  Q=$(grep -n "конец" <<<"$H" | tail -1 | cut -d: -f1)
  TAIL=$(( ${Q:-0} + 2 ))    # нет маркера вопроса → не режь, прочитай весь хвост
fi
sed -n "${TAIL},\$p" <<<"$H" | sed '/^$/d'
```



### Картинки в чат помощника
По скилла tmux раздел 3: путь как текст через `-l`, дождаться превращения пути в токен `[Image #N]` на экране, только потом Enter. Сырой путь без токена — C-u и повтор.

## Правила
1. После выполнения задачи сессия с помощником убивается. Ты не спрашивашь пользователя, а убиваешь сам.
2. Нужно параллельно несколько помощников → разные имена: `helper`, `tmux_helper`, дальше `tmux_helper_2` и т.д.
3. Правила ввода, чтения экрана и самоостановки — по скиллу tmux.
