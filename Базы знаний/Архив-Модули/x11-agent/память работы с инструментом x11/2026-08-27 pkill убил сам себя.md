# 2026-08-27: агент не запускался — pkill убивал собственную оболочку

## Симптом
Команда с `pkill -f x11_agent.py` возвращала `Exit code: -1`, и всё, что было в той же
команде после (запуск в tmux), не выполнялось. По-видимому «ничего не происходит»,
а на самом деле оболочка bash уже мертва.

## Причина 1 (главная): pkill -f совпадает с самой командой
`pkill -f x11_agent.py` матчит по **полной строке** процесса. Строка моей bash-обёртки
содержала `x11_agent.py` как аргументы, поэтому pkill убил свою же оболочку (exit -1).
То же самое для `pkill -f google-chrome`, если в тексте команды есть это слово.

### Правило (запомнить)
- Паттерн в кавычках/скобках: `pkill -f "[x]11_agent.py"` — скобки ломают самосовпадение.
- Или проверять себя: `pkill -f "python3 x11_agent.py"` (точнее, а не по одному слову).
- Не объединять pkill и запуск в одну команду — разнести на два вызова.

## Причина 2: tmux-pane с `sleep` вместо shell
Диагностика создала сессию `tmux new-session -d -s x11chk "sleep 200"`.
Тогда current_command панели = `sleep`, и `send-keys` шёл в sleep, который текст
просто игнорирует — команды «висели» на экране, не исполнясь.
Диагностика: `tmux list-panes -t <s> -F '#{pane_current_command}'` — должен быть zsh/sh.

## Причина 3 (мелочь): no server running
`tmux kill-session` убивает последнюю сессию → сервер гаснет. Нормально, не баг.

## Как решил
1. `tmux new-session -d -s x11chk -c /home/voron` — чистый zsh-панель.
2. Отдельные send-keys: сначала chrome (`google-chrome --kiosk ... &`), sleep 12,
   проверка `pgrep -cx chrome`, потом команда агента.
3. pkill/убийства процесса — в отдельных командах с паттерном `[x]11_agent.py`.

## Вывод
- Перед запуском проверять: `tmux list-panes ... current_command` == shell.
- Любое `pkill -f X` внутри строки, содержащей X = самоубийство оболочки.
- Если команда вернула exit -1 молча — первым делом искать pkill/kill в той же строке.
