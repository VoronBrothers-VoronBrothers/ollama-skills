# Скрипты клавиатуры: задержки 1с + запуск последовательностей в фоне

Дата/время: 2026-08-24 ~17:30–17:45.

## Что сделано
1. **Скрипты нажатий** (папка `/home/voron/Документы/VB-ollama/Скрипты_ИИ`):
   - `press_esc.sh` (Escape), `press_paste.sh` (Ctrl+Shift+V), `press_enter.sh` (Return).
   - Задержки `sleep` ДО и ПОСЛЕ нажатия меняли: 1с → 2с → 3с → **итоговый текущий вид: sleep 1 / sleep 1** в каждом скрипте. При необходимости легко правится edit'ом (строки со sleep в конце файла).
2. **Проблема**: последовательность из 2–3 скриптов через `&&` в одном bash-вызове оркестратора часто отменялась («command was canceled» / «pipes did not close after 1s»).
3. **Решение — запуск в фоне, оторванный от сессии оркестратора**:
   ```bash
   cd /home/voron/Документы/VB-ollama/Скрипты_ИИ && LOG=/tmp/seq_<имя>.log && rm -f $LOG \
   && nohup setsid bash -c 'bash press_esc.sh; bash press_paste.sh; bash press_enter.sh; echo "ВСЕ ГОТОВО"' >$LOG 2>&1 < /dev/null & disown
   ```
   Затем проверка: `cat /tmp/seq_<имя>.log`. Процесс живёт сам по себе (setsid+nohup), оркестратор только читает лог. Работает надёжно, отмен не было.

## Термины (разъяснения пользователю)
- **pipe / пайпинг** — `|`: вывод одной команды на вход другой (`ls | grep ...`).
- **редирект (перенаправление)** — `>файл`, `2>&1` (stderr в stdout), `>/dev/null` (в никуда).
- В xdotool-скриптах нажатия посылается как синтетическое X11-событие в конкретное окно (windowactivate + key).

## Скриншоты
`screenshot.sh` — снимок экрана 1920x1080, PNG в `/tmp/screenshot_*.png` + в буфер обмена. Финал: «command output pipes did not close after 1s» — не ошибка, скрипт отработал.

## Обновление 18:05 — как получили стабильный запуск в фоне (итерации)
Последовательность `screenshot.sh → press_esc.sh → press_paste.sh → press_enter.sh` запускали так:

| Итерация | Команда | Результат |
|---|---|---|
| 1 | просто `./screenshot.sh && ./press_esc.sh ...` в одном вызове | «command was canceled» — оркестратор режет длинную цепочку |
| 2 | `nohup bash -c '...' > /tmp/seq_run.log 2>&1 &` | сработал только скриншот, остальное (Esc/Paste/Enter) убито вместе с группой процессов; «pipes did not close after 1s» |
| 3 | `setsid nohup bash -c '...' > /tmp/seq_runN.log 2>&1 < /dev/null &` | ✅ всё четыре шага отработали в фоне, записи в логе: «Esc отправлен ✅ / Ctrl+Shift+V отправлен ✅ / Enter отправлен ✅» |

**Почему nohup не спасает:** `nohup` лишь игнорирует SIGHUP, но процесс остаётся в группе процессов вызова; когда bash-вызов оркестратора завершается (т.ч. с «pipes did not close after 1s»), вся группа убивается — выживает только то, что уже успело записаться в лог.
**Почему setsid спасает:** `setsid` создаёт новую сессию/процесс-группу (полное отсоединение от группы оркестратора) — kill группы её не трогает. `< /dev/null` закрывает stdin, чтобы pipe не держался открытым и вызов возвращался сразу.

**Финальный надёжный шаблон:**
```bash
cd /home/voron/Документы/VB-ollama/Скрипты_ИИ && setsid nohup bash -c './screenshot.sh && ./press_esc.sh && ./press_paste.sh && ./press_enter.sh' > /tmp/seq_runN.log 2>&1 < /dev/null & echo "PID=$!"
```
Проверка после (~9 c на всю цепочку): `sleep 9; cat /tmp/seq_runN.log; ps -p PID`.
Предупждение «Error: command output pipes did not close after 1s» при таком запуске — безвредно, просто pipe удерживался живой сессией.
**Важно:** фокус клавиатуры (xdotool key) уходит в АКТИВНОЕ окно в момент нажатия — перед запуском убедиться, что нужное окно (ollama-TUI/браузер) активно; либо передавать id окна аргументом скриптам (`press_esc.sh <PID>` / `press_paste.sh <X11-id>`).
