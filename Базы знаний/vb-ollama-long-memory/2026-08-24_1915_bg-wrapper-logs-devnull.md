# bg.sh — обёртка фоновых скриптов, ВСЕ ЛОГИ В /dev/null (правило экспертности)

Дата/время: 2026-08-24 ~19:07–19:15.

## Правило
Мы с оркестратором — эксперты в логировании: **все логи фоновых скриптов → /dev/null**.
Лог-файлы больше не плодим (зрение.log и т.п.) — только если нужно специально читать вывод.

## Что сделано
1. **`bg.sh`** (`/home/voron/Документы/VB-ollama/Скрипты_ИИ/bg.sh`) — обёртка:
   ```bash
   cd /home/voron/Документы/VB-ollama/Скрипты_ИИ
   ./bg.sh ./зрение.sh [аргументы...]
   ```
   Внутри: `setsid` + stdout/stderr/stdin → `/dev/null` + `disown`. Отрывается от сессии оркестратора (нет «command was canceled» / «pipes did not close»), CWD — папка скрипта, кириллица в путях не ломает.
2. **Зрение** запускается через обёртку: `./bg.sh ./зрение.sh`.
3. Два скрипта подряд: `./bg.sh ./скрипт1.sh && sleep N && ./bg.sh ./скрипт2.sh`.

## Корень проблем (история)
- Простой `nohup ... &` убивался harness'ом ollama («command output pipes did not close after 1s») — процесс роняли, скрипт не доезжал (видимо, в свёрнутом/неактивном окне xdotool не доставлял нажатия → Chrome «Работа Chrome была завершена некорректно»).
- `setsid` + `disown` + полное отключение пайпов решили проблему: скрипты доходят до конца.
