## What is Instructor?

**Instructor** — это Python-библиотека для получения **структурированных и предсказуемых данных** из языковых моделей (LLM), таких как GPT-4 и Claude.

- Работает как «форма», которую LLM заполняет по заданной структуре.
- Обеспечивает валидацию, автоматическое исправление ошибок и стабильный формат вывода.

### Интеграция в приложение

```
flowchart LR
    A[Your Application] --> B[Instructor]
    B --> C[LLM Provider]
    C --> B
    B --> A
```

---

## Проблемы, которые решает Instructor

- **Непредсказуемый вывод**: LLM может менять формат ответа при каждом вызове.
- **Ошибки формата**: Сложно гарантировать валидность JSON или других структур.
- **Необходимость ручной валидации**: Требуется проверка соответствия ожидаемому формату.

### Решения от Instructor

- **Определение структуры через Python-классы** (Pydantic).
- **Гарантированное соответствие формата** на уровне API.
- **Автоматическая валидация и исправление ошибок**.

---

## Пример использования

```python
import instructor
from pydantic import BaseModel

class Person(BaseModel):
    name: str
    age: int
    city: str

client = instructor.from_provider("openai/gpt-4o-mini")

person = client.create(
    response_model=Person,
    messages=[
        {"role": "user", "content": "Extract: John is 30 years old and lives in New York."}
    ]
)

print(f"Name: {person.name}")  # John
print(f"Age: {person.age}")    # 30
print(f"City: {person.city}")  # New York
```

## Ключевые концепции

### 1. Response Models (Модели ответа)

- Определяют структуру ожидаемого вывода.
- Реализуются с помощью **Pydantic**.
- Поддерживают описания полей (`Field(description=...)`), которые помогают LLM точнее извлекать данные.

```python
from pydantic import BaseModel, Field

class User(BaseModel):
    name: str = Field(description="The user's full name")
    age: int = Field(description="The user's age in years")
```

### 2. Client Setup

- Метод `instructor.from_provider()` подключает Instructor к LLM-провайдеру.
- Автоматически обрабатывает конфигурацию провайдера.

```python
client = instructor.from_provider("openai/gpt-4o-mini")
client = instructor.from_provider("anthropic/claude-3-5-haiku-latest")
client = instructor.from_provider("google/gemini-3-flash")
```

### 3. Modes (Режимы)

- Определяют, как Instructor взаимодействует с LLM для получения структурированного вывода.
- Разные провайдеры поддерживают разные режимы.
- Режим выбирается автоматически, но может быть задан вручную.

---

## Типичные сценарии использования

- **Data extraction**: Извлечение структурированной информации из текста.
- **Form filling**: Преобразование свободного текста в поля формы.
- **Classification**: Классификация контента по заданным категориям.
- **Content generation**: Генерация структурированного контента (статьи, описания товаров).
- **API integration**: Приведение вывода LLM к формату, требуемому API.

## Валидация и обработка ошибок

Используется валидация Pydantic. При несоответствии — автоматический повторный запрос (retry) с обратной связью.

```python
from pydantic import BaseModel, Field, field_validator

class User(BaseModel):
    name: str
    age: int = Field(gt=0, lt=120)

    @field_validator('name')
    def name_must_have_space(cls, v):
        if ' ' not in v:
            raise ValueError('Name must include first and last name')
        return v

user = client.create(
    response_model=User,
    messages=[
        {"role": "user", "content": "Extract: Tom is 25 years old."}
    ],
)
```

> **Важно**: `Field(...)` и `@field_validator` позволяют задавать ограничения и кастомные правила.

## Почему стоит использовать `instructor`?

### Проблема: ненадёжные неструктурированные ответы от LLM

Без `instructor` вы получаете **текст**, а не структурированные данные:

```python
# Что вы хотите:
user_info = extract_user("John is 25 years old")
print(user_info.name)  # "John"
print(user_info.age)   # 25

# Что вы получаете на практике:
response = llm.complete("Extract: John is 25 years old")
# "I'd be happy to help! Based on the text, the user's name is John
# and their age is 25. Is there anything else you'd like me to extract?"

# Теперь нужно:
# 1. Парсить текст вручную
# 2. Обрабатывать синтаксические ошибки JSON
# 3. Валидировать данные
# 4. Повторять запрос при ошибках (а они будут)
# 5. Писать отдельный код под каждый API провайдера
```

### Решение: `instructor` + Pydantic

```python
import instructor
from pydantic import BaseModel

class User(BaseModel):
name: str
age: int

client = instructor.from_provider("openai/gpt-4o-mini")
user = client.create(
response_model=User,
messages=[{"role": "user", "content": "John is 25 years old"}],
)

print(user.name)  # "John"
print(user.age)   # 25
```

✅ Без парсинга
✅ Без ручных retry-логик
✅ Без провайдерозависимого кода

## Ключевые задачи, которые решает `instructor`

### 1. Надёжность: автоматические повторы при валидации

```python
# Без instructor — хрупкий код:
try:
data = json.loads(llm_response)
user = User(**data)  # KeyError: 'name'
except Exception as e:
# Что делать? Retry? Парсить текст?
pass

# С instructor — надёжно:
user = client.create(
response_model=User,
messages=[{"role": "user", "content": "..."}],
max_retries=3,  # Автоматические повторы при ошибках валидации
)
# Возвращает валидный `User` или выбрасывает исключение
```

### 2. Унификация API: один интерфейс для всех провайдеров

```python
# OpenAI:
client = instructor.from_provider("openai/gpt-4o-mini")

# Anthropic:
client = instructor.from_provider("anthropic/claude-3")

# Google:
client = instructor.from_provider("google/gemini-pro")

# Одинаковый вызов:
user = client.create(
response_model=User,
messages=[{"role": "user", "content": "..."}],
)
```

### 3. Сложные структуры данных — как в Python

```python
from typing import List

class Address(BaseModel):
street: str
city: str

class User(BaseModel):
name: str
addresses: List[Address]

class UserList(BaseModel):
users: List[User]

result = client.create(
response_model=UserList,
messages=[{"role": "user", "content": "..."}],
)
```

## Архитектура библиотеки `instructor`

### Основной поток выполнения (High-Level Flow)

```mermaid
sequenceDiagram
autonumber
participant U as User Code
participant I as Instructor (patched)
participant R as Retry Layer (tenacity)
participant C as Provider Client
participant D as Dispatcher (process_response)
participant H as Provider Handler (response/reask)
participant M as Pydantic Model

U->>I: chat.completions.create(response_model=..., **kwargs)
Note right of I: patch() оборачивает create() кэшированием, шаблонизацией, retry и хуками
I->>R: retry_sync/async(func=create, max_retries, strict, mode, hooks)
loop attempts
R->>C: create(**prepared_kwargs)
C-->>R: raw response (provider-specific)
R->>D: process_response(_async)(response, response_model, mode, stream)
alt Streaming/Partial
D->>M: Iterable/Partial.from_streaming_response(_async)
D-->>R: Iterable/Partial model (или список элементов)
else Standard
D->>H: provider mode handler (format/parse selection)
H-->>D: adjusted response_model/new_kwargs при необходимости
D->>M: response_model.from_response(...)
M-->>D: parsed model (с _raw_response)
D-->>R: model (или адаптированный простой тип)
end
R-->>I: parsed model
end
I-->>U: final model (+ _raw_response на экземпляре)

rect rgb(255,240,240)
Note over R,H: При ошибках валидации/JSON → путь reask
R->>H: handle_reask_kwargs(..., exception, failed_attempts)
H-->>R: новые kwargs/messages для следующей попытки
end
```

#### Ключевые компоненты и их ответственность

- **`patch()`**
Оборачивает `create()` провайдера, добавляя:
- кэширование (lookup/save)
- шаблонизацию (`prompt_template`)
- строгий режим (`strict`)
- хуки (`hooks`)
- retry-логику

- **Retry Layer**
Выполняет вызов провайдера, управляет:
- повторами при ошибках валидации/JSON
- хуками (emit/update)
- подсчётом usage
- подготовкой `reask`-запросов

- **Dispatcher**
Выбирает путь парсинга по `Mode`, обрабатывает:
- multimodal message conversion
- привязку `_raw_response`
- потоковый/частичный вывод

- **Provider Handlers**
Реализуют специфичные для провайдера логики:
- форматирование запроса
- обработка reask (в т.ч. добавление error feedback в messages)

### Минимальные синхронные и асинхронные пути

#### Синхронный вызов
```python
import instructor
from pydantic import BaseModel

class User(BaseModel):
name: str
age: int

client = instructor.from_provider("openai/gpt-4o-mini")

model = client.create(
model="gpt-4o-mini",

max_retries=3,
strict=True,
)

raw = model._raw_response
```

#### Асинхронный вызов
```python
import asyncio
import instructor
from pydantic import BaseModel

class User(BaseModel):
name: str
age: int

async def main():
aclient = instructor.from_provider("openai/gpt-4o-mini", async_client=True)
model = await aclient.create(
model="gpt-4o-mini",
messages=[{"role": "user", "content": "{\"name\": \"Ada\", \"age\": 37}"}],
response_model=User,
max_retries=3,
strict=True,
)
print(model)

asyncio.run(main())
```

### Режимы работы: streaming, partial, parallel

#### `create_iterable`
- Используется через `client.create_iterable(messages=..., response_model=Model)`
- Возвращает генератор (sync) или async generator
- Внутри включает `stream=True`, использует `IterableBase.from_streaming_response(_async)`

```python
for item in client.create_iterable(messages=..., response_model=MyModel):
print(item)
```

#### `create_partial`
- Используется через `client.create_partial(messages=..., response_model=Model)`
- Возвращает частично заполненные модели по мере прихода токенов
- Внутри оборачивает модель как `Partial[Model]`, включает `stream=True`

```python
for partial in client.create_partial(messages=..., response_model=MyModel):
# partial содержит поля по мере их поступления
pass
```

#### `Mode.PARALLEL_TOOLS`
- Используется с типами-списками: `response_model=[Model1, Model2]`
- Выполняет несколько tool calls в одном запросе
- **Streaming не поддерживается**

```python
from instructor.mode import Mode

result = client.create(
model="gpt-4o",
messages=[{"role": "user", "content": "Извлеки информацию о человеке и событии."}],
response_model=[PersonInfo, EventInfo],
mode=Mode.PARALLEL_TOOLS,
)
```

### Хуки и retry

#### Поддерживаемые события (HookName)
- `completion:kwargs` — перед вызовом провайдера
- `completion:response` — после получения ответа
- `parse:error` — при ошибках валидации/JSON
- `completion:last_attempt` — перед завершением retry-последовательности
- `completion:error` — ошибки, не связанные с парсингом

#### Пример использования хуков
```python
from instructor.core.hooks import HookName

client.on(HookName.COMPLETION_KWARGS, lambda **kw: print("KWARGS", kw))
client.on(HookName.PARSE_ERROR, lambda e: print("PARSE", e))
```

### Конвертация multimodal-данных

- Происходит в `processing.multimodal.convert_messages`
- Автоматическое определение типов (изображения/аудио/PDF)
- Поддержка:
- строковых путей
- URL
- data URIs
- Преобразование в provider-ready payload (например, base64 + MIME-type)

### Обработка ошибок

| Сценарий | Поведение |
|---------|-----------|
| Ошибка валидации / JSON decode | Триггерит reask: добавляется error feedback в `messages`, повторный вызов |
| Все попытки исчерпаны | Поднимается `InstructorRetryException` с полями: `failed_attempts`, `last_completion`,
`usage`, `kwargs` |

### Расширяемость

- **Новые провайдеры**
Добавляют:
- обработчики ответов и reask
- регистрацию поддерживаемых режимов в dispatcher

- **Повторное использование**
Большинство JSON/tool-паттернов общие — предпочтительно использовать существующие handlers.

- **Разделение логики**
Provider-specific код — только в utils провайдера; центральный dispatcher отвечает только за маршрутизацию и
оркестрацию.

### Отслеживание потока выполнения через хуки

Хуки позволяют вмешиваться в ключевые этапы без изменения ядра:

```python
from instructor.core.hooks import HookName

client.on(HookName.COMPLETION_KWARGS, lambda **kw: print("KWARGS:", kw))
client.on(HookName.COMPLETION_RESPONSE, lambda resp: print("RESPONSE:", type(resp)))
client.on(HookName.PARSE_ERROR, lambda e: print("PARSE ERROR:", e))
client.on(HookName.COMPLETION_LAST_ATTEMPT, lambda e: print("LAST ATTEMPT:", e))
client.on(HookName.COMPLETION_ERROR, lambda e: print("COMPLETION ERROR:", e))
```

**Типичные сценарии использования:**
- Запись `kwargs`, передаваемых провайдеру (включая mode/tools/response_format)
- Сохранение сырых ответов для оффлайн-анализа
- Анализ ошибок парсинга и изменений в `messages` при reask

> **Важно:** Хукам, принимающим `**kwargs`, передаётся метаданный словарь `_instructor_meta` с полями:
> - `attempt_number`
> - `correlation_id`
> - `mode`
> - `response_model_name`

Пример:
```python
client.on(HookName.COMPLETION_KWARGS, lambda **kw: print(kw.get("_instructor_meta")))
```

### Обработка ошибок и retry

При исчерпании всех попыток вызывается `InstructorRetryException`:

```python

```

### Строгий vs нестрогий парсинг

| Параметр | Поведение |
|---------|-----------|
| `strict=True` | Требует точного соответствия схеме; выявляет расхождения на ранней стадии |
| `strict=False` | Пропускает лишние поля, допускает нестрогие типы (например, `float` вместо `int`) |

Пример:
```python
client.create(..., response_model=MyModel, strict=True)
```

```python
max_retries = Retrying(stop=stop_after_attempt(3) | stop_after_delay(10))

```

**Применение:** баланс между надёжностью и задержкой.

## Инструкция по сравнению режимов Instructor

### Общие положения

- Instructor использует **ядерные (core) режимы**, которые работают кросспровайдерно.
- Режимы, специфичные для провайдера, поддерживаются, но объявлены устаревшими и вызывают предупреждения.
- Логика обработки режимов перенесена в обработчики провайдеров; DSL больше не хранит логику потоковой передачи
(streaming), зависящую от режима.

---

### Ядерные режимы

- **`TOOLS`** — вызов инструментов/функций для структурированного извлечения данных.
- **`JSON_SCHEMA`** — нативная поддержка схемы, если провайдер её поддерживает.
- **`MD_JSON`** — извлечение JSON из текста или кодовых блоков; используется как резервный или для простых случаев.
- **`PARALLEL_TOOLS`** — параллельные вызовы нескольких инструментов в одном ответе.
- **`RESPONSES_TOOLS`** — инструменты API OpenAI Responses.

---

### Устаревшие режимы (deprecated)

Устаревшие режимы маппятся на ядерные:

| Устаревший режим | → | Ядерный режим |
|------------------|----|---------------|
| `FUNCTIONS`      | → | `TOOLS`       |
| `TOOLS_STRICT`   | → | `TOOLS`       |
| `ANTHROPIC_TOOLS`| → | `TOOLS`       |
| `ANTHROPIC_JSON` | → | `MD_JSON`     |
| `GENAI_TOOLS`    | → | `TOOLS`       |
| `GENAI_JSON`     | → | `JSON_SCHEMA` *(примечание: в документе указано как `JSON`, но маппинг на ядерный режим —
`JSON_SCHEMA`)* |
| `MISTRAL_TOOLS`  | → | `TOOLS`       |
| `MISTRAL_STRUCTURED_OUTPUTS` | → | `JSON_SCHEMA` |
| `BEDROCK_TOOLS`  | → | `TOOLS`       |
| `BEDROCK_JSON`   | → | `MD_JSON`     |
| `FIREWORKS_TOOLS`| → | `TOOLS`       |
| `FIREWORKS_JSON` | → | `MD_JSON`     |
| `CEREBRAS_TOOLS` | → | `TOOLS`       |
| `CEREBRAS_JSON`  | → | `MD_JSON`     |
| `WRITER_TOOLS`   | → | `TOOLS`       |
| `WRITER_JSON`    | → | `MD_JSON`     |
| `PERPLEXITY_JSON`| → | `MD_JSON`     |
| `VERTEXAI_TOOLS` | → | `TOOLS`       |
| `VERTEXAI_JSON`  | → | `MD_JSON`     |
| `VERTEXAI_PARALLEL_TOOLS` | → | `PARALLEL_TOOLS` |

> ⚠ Устаревшие режимы следует использовать только для обратной совместимости.

### Рекомендации по выбору режима

- **`TOOLS`** — рекомендуется для большинства случаев структурированного вывода.
- **`JSON_SCHEMA`** — при наличии нативной поддержки схемы провайдером (например, OpenAI, Mistral).
- **`MD_JSON`** — если инструменты не поддерживаются или требуется простой fallback.

## Основные принципы философии Instructor

- **Простота превосходит сложность**: инструмент должен упрощать
сложное, не усложняя простое.
- **Опора на знакомые технологии**: использует Pydantic как основу —
никаких новых абстракций.
- **Полный контроль над кодом**: «выход» всегда открыт; можно
использовать raw API без фреймворка.
- **Прозрачность**: видно, что именно отправляется в LLM и какие
ответы приходят.
- **Композиция вместо конфигурации**: строится через функции, а не
YAML/декораторы/магию.
- **Эволюционное развитие кода**: можно начинать с простого и
постепенно добавлять валидацию, retry, streaming и т.д.

## Ключевые принципы

### 1. Начинайте с того, что знают разработчики
- Instructor **не изобретает** новых абстракций.
- Основа — `pydantic.BaseModel`.
- Пример:

```python
import instructor
from pydantic import BaseModel

class User(BaseModel):
name: str
age: int

client = instructor.from_provider("openai/gpt-4.1-mini")
_user = client.create(
response_model=User,
messages=[{"role": "user", "content": "Jane is 33"}],
)
```

### 2. «Выход» всегда доступен
- Instructor **не упаковывает**, а **патчит** существующие клиенты.
- Можно переключиться на raw API в одну строку:

```python
# Без response_model — raw вызов
client = instructor.from_provider("openai/gpt-4.1-mini")
_result = client.create(messages=[{"role": "user", "content": "Say
hello"}])

# Или напрямую через OpenAI SDK
from openai import OpenAI
_raw_client = OpenAI()
```

### 3. Прозрачность вместо сокрытия
- Можно получить сырую ответную часть от LLM:

```python
_raw_response = result._raw_response
```

- Поддержка логирования через `logfire`:

```python
instructor.logfire.configure()
```

### 4. Композиция вместо конфигурации
- Нет YAML, декораторов или магии.
- Пример композиции:

```python
class User(BaseModel):
name: str
age: int

class Company(BaseModel):
name: str
industry: str

class Analysis(BaseModel):
user: User
company: Company

def extract_user(text: str) -> User:
return client.create(response_model=User, messages=[{"role":
"user", "content": text}])

def extract_company(text: str) -> Company:
return client.create(response_model=Company, messages=[{"role":
"user", "content": text}])

def analyze_email(email: str) -> Analysis:
user = extract_user(email)
company = extract_company(email)
return Analysis(user=user, company=company)
```

### 5. Рост от простого к сложному
- Без рефакторинга можно добавлять функционал:

```python
# День 1: базовый вызов
_user = client.create(response_model=User, messages=[...])

# День 7: валидация
class User(BaseModel):
name: str
age: int

@field_validator("age")
def check_age(cls, value: int) -> int:
if value < 0 or value > 150:
raise ValueError("Invalid age")
return value

# День 14: retry
_user = client.create(response_model=User, messages=[...],
max_retries=3)

# День 30: стриминг
from instructor import Partial

for partial in client.create(
response_model=Partial[User],
messages=[...],
stream=True,
):
update_ui(partial)
```

```python
_messages = [

```

```
## DSL-компоненты

Позволяют задавать сложные паттерны поведения и структуры данных:

- **`iterable`** — для генерации списков/итераций.
- **`partial`** — для частичного заполнения структур (например,
пошаговое заполнение полей).
- **`parallel`** — для параллельных вызовов LLM.
- **`maybe`** — для опциональных значений (аналог `Optional[T]`).
- **`citation`** — добавление цитат/источников к ответам.

## Вызовы функций и схемы

- **`function_calls`** — базовые утилиты для работы с вызовами
функций.
- **`OpenAISchema`** — декоратор, превращающий Pydantic-модель
в схему для OpenAI Function Calling.
- **`openai_schema()`** — генерирует JSON Schema из Pydantic-класса
(совместимая с OpenAI).
- **`generate_openai_schema()`**, **`generate_anthropic_schema()`**,
**`generate_gemini_schema()`** — генерация схем под конкретные API
провайдеров.

## Валидация

- **`validation`** — модуль, содержащий инструменты валидации.
- **`llm_validator`** — валидатор, использующий LLM для проверки
корректности ответа (например: «ответ должен содержать хотя бы один
URL»).
- **`openai_moderation`** — интеграция с OpenAI Moderation API для
фильтрации небезопасного контента.

## Пакетная обработка

- **`batch`**, **`BatchProcessor`**, **`BatchRequest`**,
**`BatchJob`** — инструменты для массовой отправки запросов и
обработки результатов пачками (например, обработка 1000+ запросов с
лимитами).

## Дистилляция и fine-tuning

- **`distil`**, **`FinetuneFormat`1**, **`Instructions`** — утилиты для
подготовки данных к fine-tuning и дистилляции моделей.

## Мультимодальные данные

- **`multimodal`**, **`Image`**, **`Audio`** — поддержка изображений и
аудио в запросах (например, передача base64-encoded данных или URL).

## Режимы и провайдеры

- **`Mode`** — перечисление режимов работы (`TOOL`, `FUNCTIONS`,
`JSON_MODE`, и т.д.).
- **`Provider`** — перечисление поддерживаемых LLM-провайдеров
(OpenAI, Anthropic, Gemini и др.).

## Исключения

- **`exceptions`** — набор пользовательских исключений для обработки
ошибок API (например: `RetryableError`, `ValidationError`,
`APIConnectionError`).

## Хуки (Hooks)

Система событий для отслеживания и перехвата вызовов LLM:

- **`hooks`**, **`Hooks`**, **`HookName`** — позволяют подписаться на
события: `before_call`, `after_call`, `on_error`, `on_response`.

## Патчинг методов

- **`patch()`**, **`apatch()`** — декораторы, «подменяющие» методы
клиентов (например, `openai.ChatCompletion.create`) для автоматической
обработки схем и валидации.
```

# Конспект: Вклад в библиотеку Instructor

## Способы участия

### Тесты на оценку качества (Evals)

- **Цель**: мониторинг качества моделей OpenAI и самой библиотеки
Instructor.
- **Процесс вклада**:
- Изучить существующие evals:
[`tests/llm/test_openai/evals`](https://github.com/instructor-ai/instru[`tests/llm/test_openai/evals`](https:/github.com/instructor-ai/instructor/tree/main/tests/llm/test_openai/evals)
- Создать новый `pytest`-тест, оценивающий конкретную
функциональность или граничные случаи
- Следовать структуре существующих тестов
- Отправить PR для ревью и интеграции
- **Запуск**: evals выполняются еженедельно, результаты отслеживаются
во времени.

### Сообщение об ошибках (Issues)

При создании issue указать:
- Чёткий заголовок
- Подробности:
- `response_model`
- `messages`, отправленные в API
- Используемая модель (`model`)
- Шаги для воспроизведения
- Ожидаемое и фактическое поведение
- Окружение: Python, OS, версии пакетов

### Вклад кода (Pull Requests)

- **Малые изменения**: можно сразу отправлять PR.
- **Крупные изменения**: сначала создать issue для обсуждения подхода.
- Идеи для вклада: метки [`help
wanted`](https://github.com/instructor-ai/instructor/labels/help%20wantwanted`](https://github.com/instructor-i/instructor/labels/help%20wanted), [`goodfirst
issue`](https://github.com/instructor-ai/instructor/labels/good%20firstissue`](https://github.com/instructor-ai/instructor/laels/good%20first%20issue).

## Стиль кода

### Общие правила

- Использовать строгую типизацию (`from __future__ import
annotations`)
- Порядок импортов: стандартная библиотека → сторонние →
локальные
- `snake_case` для функций/переменных, `PascalCase` для классов
- Полные docstrings для публичного API

### Условные комментарии (Conventional Comments)

Формат:
```
<label>: <subject>

<description>
```

**Типы меток**:
- `praise:` — положительный момент
- `suggestion:` — предложение улучшения
- `question:` — вопрос для уточнения
- `issue:` — проблема, требующая исправления
- `todo:` — отложенное действие
- `fix:` — исправление

Пример:
```
suggestion: use a validator for this field
This would ensure the value is always properly formatted.
```

### Соглашение о коммитах (Conventional Commits)

Формат:
```
<type>[optional scope]: <description>

[optional body]

[optional footer]
```

**Типы**:
- `feat`: новая функция
- `fix`: исправление бага
- `docs`: изменения в документации
- `style`: форматирование
- `refactor`: рефакторинг без изменений поведения
- `test`: добавление/исправление тестов
- `chore`: технические задачи

**Примеры**:
```
feat(openai): add streaming response support
fix(anthropic): resolve tool calling response format
docs: update installation instructions
test(evals): add new recursive schema test cases
```

Для ломающих изменений добавить `!` перед `:`:
```
feat(api)!: change return type of from_openai function
```

## Документация

### Структура и правила

- Все документы — в Markdown (`docs/`)
- При добавлении страницы: обновить `mkdocs.yml`
- Локальный предпросмотр: `mkdocs serve`
- **Стиль**:
- Уровень чтения ~10 класс (простой и ясный язык)
- Полные примеры кода с импортами
- Ссылки на смежные разделы
- Единообразное форматирование

### Пример документационного блока

```python
# Complete example with imports
import instructor
from pydantic import BaseModel

class Person(BaseModel):
name: str
age: int

client = instructor.from_provider("openai/gpt-5-nano")

person = client.create(
model="gpt-5.4-mini",
response_model=Person,
messages=[
{"role": "user", "content": "Extract: John Doe is 25 years
old"}
]
)

print(person.name)  # "John Doe"
print(person.age)   # 25
```

### Особенности Markdown в документации

- **Выделение строк кода**:
````markdown
```python hl_lines="2 3"
def example():
# This line is highlighted
# This line is also highlighted
return "normal line"
```
````

- **Адмониции (callout boxes)**:
```markdown
!!! note "Optional Title"
Это примечание.

!!! warning
Это предупреждение.
```
