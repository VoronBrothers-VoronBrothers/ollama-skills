## Основные клиенты (Core Clients)

- **`Instructor`** — синхронный клиент для взаимодействия с
LLM-провайдерами.
- **`AsyncInstructor`** — асинхронный клиент для работы с LLM.
- **`Response`** — структура, возвращаемая после вызова LLM; содержит
результат и метаданные.

> Core modes — рекомендуемый способ использования API. Устаревшие
провайдер-специфичные режимы поддерживаются, но генерируют
предупреждения.

## Создание клиентов

- **`from_provider()`** — универсальная функция для создания клиента
из любого поддерживаемого провайдера.
- **`from_openai()`** — создает клиент на основе OpenAI SDK.
- **`from_litellm()`** — создает клиент через LiteLLM (поддержка
множества API совместимых с OpenAI).

## DSL-компоненты

Позволяют задавать сложные паттерны поведения и структуры данных:

- **`iterable`** — для генерации списков/итераций.
- **`partial`** — для частичного заполнения структур (например,
пошаговое заполнение полей).
- **`parallel`** — для параллельных вызовов LLM.
- **`maybe`** — для опциональных значений (аналог `Optional[T]`).
- **`citation`** — добавление цитат/источников к ответам.

## Вызовы функций и схемы

- **`function_calls`** — базовые утилиты для работы с вызовами
функций.
- **`OpenAISchema`** — декоратор, превращающий Pydantic-модель
в схему для OpenAI Function Calling.
- **`openai_schema()`** — генерирует JSON Schema из Pydantic-класса
(совместимая с OpenAI).
- **`generate_openai_schema()`**, **`generate_anthropic_schema()`**,
**`generate_gemini_schema()`** — генерация схем под конкретные API
провайдеров.

## Валидация

- **`validation`** — модуль, содержащий инструменты валидации.
- **`llm_validator`** — валидатор, использующий LLM для проверки
корректности ответа (например: «ответ должен содержать хотя бы один
URL»).
- **`openai_moderation`** — интеграция с OpenAI Moderation API для
фильтрации небезопасного контента.

## Пакетная обработка

- **`batch`**, **`BatchProcessor`**, **`BatchRequest`**,
**`BatchJob`** — инструменты для массовой отправки запросов и
обработки результатов пачками (например, обработка 1000+ запросов с
лимитами).

## Дистилляция и fine-tuning

- **`distil`**, **`FinetuneFormat`1**, **`Instructions`** — утилиты для
подготовки данных к fine-tuning и дистилляции моделей.

## Мультимодальные данные

- **`multimodal`**, **`Image`**, **`Audio`** — поддержка изображений и
аудио в запросах (например, передача base64-encoded данных или URL).

## Режимы и провайдеры

- **`Mode`** — перечисление режимов работы (`TOOL`, `FUNCTIONS`,
`JSON_MODE`, и т.д.).
- **`Provider`** — перечисление поддерживаемых LLM-провайдеров
(OpenAI, Anthropic, Gemini и др.).

## Исключения

- **`exceptions`** — набор пользовательских исключений для обработки
ошибок API (например: `RetryableError`, `ValidationError`,
`APIConnectionError`).

## Хуки (Hooks)

Система событий для отслеживания и перехвата вызовов LLM:

- **`hooks`**, **`Hooks`**, **`HookName`** — позволяют подписаться на
события: `before_call`, `after_call`, `on_error`, `on_response`.

## Патчинг методов

- **`patch()`**, **`apatch()`** — декораторы, «подменяющие» методы
клиентов (например, `openai.ChatCompletion.create`) для автоматической
обработки схем и валидации.
