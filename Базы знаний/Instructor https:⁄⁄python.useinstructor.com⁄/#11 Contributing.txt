# Конспект: Вклад в библиотеку Instructor

## Способы участия

### Тесты на оценку качества (Evals)

- **Цель**: мониторинг качества моделей OpenAI и самой библиотеки
Instructor.
- **Процесс вклада**:
- Изучить существующие evals:
[`tests/llm/test_openai/evals`](https://github.com/instructor-ai/instru[`tests/llm/test_openai/evals`](https:/github.com/instructor-ai/instructor/tree/main/tests/llm/test_openai/evals)
- Создать новый `pytest`-тест, оценивающий конкретную
функциональность или граничные случаи
- Следовать структуре существующих тестов
- Отправить PR для ревью и интеграции
- **Запуск**: evals выполняются еженедельно, результаты отслеживаются
во времени.

### Сообщение об ошибках (Issues)

При создании issue указать:
- Чёткий заголовок
- Подробности:
- `response_model`
- `messages`, отправленные в API
- Используемая модель (`model`)
- Шаги для воспроизведения
- Ожидаемое и фактическое поведение
- Окружение: Python, OS, версии пакетов

### Вклад кода (Pull Requests)

- **Малые изменения**: можно сразу отправлять PR.
- **Крупные изменения**: сначала создать issue для обсуждения подхода.
- Идеи для вклада: метки [`help
wanted`](https://github.com/instructor-ai/instructor/labels/help%20wantwanted`](https://github.com/instructor-i/instructor/labels/help%20wanted), [`goodfirst
issue`](https://github.com/instructor-ai/instructor/labels/good%20firstissue`](https://github.com/instructor-ai/instructor/laels/good%20first%20issue).

## Стиль кода

### Общие правила

- Использовать строгую типизацию (`from __future__ import
annotations`)
- Порядок импортов: стандартная библиотека → сторонние →
локальные
- `snake_case` для функций/переменных, `PascalCase` для классов
- Полные docstrings для публичного API

### Условные комментарии (Conventional Comments)

Формат:
```
<label>: <subject>

<description>
```

**Типы меток**:
- `praise:` — положительный момент
- `suggestion:` — предложение улучшения
- `question:` — вопрос для уточнения
- `issue:` — проблема, требующая исправления
- `todo:` — отложенное действие
- `fix:` — исправление

Пример:
```
suggestion: use a validator for this field
This would ensure the value is always properly formatted.
```

### Соглашение о коммитах (Conventional Commits)

Формат:
```
<type>[optional scope]: <description>

[optional body]

[optional footer]
```

**Типы**:
- `feat`: новая функция
- `fix`: исправление бага
- `docs`: изменения в документации
- `style`: форматирование
- `refactor`: рефакторинг без изменений поведения
- `test`: добавление/исправление тестов
- `chore`: технические задачи

**Примеры**:
```
feat(openai): add streaming response support
fix(anthropic): resolve tool calling response format
docs: update installation instructions
test(evals): add new recursive schema test cases
```

Для ломающих изменений добавить `!` перед `:`:
```
feat(api)!: change return type of from_openai function
```

## Документация

### Структура и правила

- Все документы — в Markdown (`docs/`)
- При добавлении страницы: обновить `mkdocs.yml`
- Локальный предпросмотр: `mkdocs serve`
- **Стиль**:
- Уровень чтения ~10 класс (простой и ясный язык)
- Полные примеры кода с импортами
- Ссылки на смежные разделы
- Единообразное форматирование

### Пример документационного блока

```python
# Complete example with imports
import instructor
from pydantic import BaseModel

class Person(BaseModel):
name: str
age: int

client = instructor.from_provider("openai/gpt-5-nano")

person = client.create(
model="gpt-5.4-mini",
response_model=Person,
messages=[
{"role": "user", "content": "Extract: John Doe is 25 years
old"}
]
)

print(person.name)  # "John Doe"
print(person.age)   # 25
```

### Особенности Markdown в документации

- **Выделение строк кода**:
````markdown
```python hl_lines="2 3"
def example():
# This line is highlighted
# This line is also highlighted
return "normal line"
```
````

- **Адмониции (callout boxes)**:
```markdown
!!! note "Optional Title"
Это примечание.

!!! warning
Это предупреждение.
```

## Скрипты поддержки документации

| Скрипт | Назначение | Требования |
|--------|------------|-------------|
| `make_clean.py` | Очистка Markdown-файлов | — |
| `check_blog_excerpts.py` | Валидация блог-постов | — |
| `make_sitemap.py` | Генерация sitemap с AI-анализом |
`OPENAI_API_KEY`, `openai`, `typer`, `rich`, `tenacity`, `pyyaml` |

**Запуск вручную**:
```bash
python scripts/make_clean.py --dry-run
python scripts/check_blog_excerpts.py
python scripts/make_sitemap.py --root-dir docs --output-file
sitemap.yaml
```

**Pre-commit**: автоматически запускаются при коммитах в `docs/`.

- `documentation-sync`: согласование кода и docs

```bash
gh pr create -t "Your feature title" -b "Description of your changes"
-r jxnl,ivanleomk
```

[Cursor](https://cursor.sh)`
