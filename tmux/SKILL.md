# tmux — военный стандарт автономности

## 1. Гарантированный запуск (Защита от гонок хоста)
Имя сессии должно быть уникальным (например, с хвостом PID `_$$`), чтобы параллельные процессы ИИ не пересекались. Фиксированные `sleep` запрещены — готовность проверяется циклическим опросом маркера интерфейса.

```bash
# Инициализация изолированной сессии
tmux kill-session -t ohelp_\[ 2>/dev/null; tmux new-session -d -s ohelp_\]

# Опрос готовности интерфейса (макс 5 секунд, шаг 0.2с) вместо слепого sleep
for i in {1..25}; do 
  if tmux capture-pane -t ohelp_\$\$ -p | grep -q ">>>"; then break; fi
  sleep 0.2
done
```

## 2. Жесткие правила ввода (Синтаксис без исключений)
При заполнении полей ввода и отправке команд строго разделять текстовые литералы и управляющие клавиши.

* **Текст / Пути к файлам:** Только через `tmux send-keys -t s -l -- "данные"`. Строго один текстовый аргумент. Флаг `-l` превращает ВСЕ последующие слова в текст.
* **Клавиши управления:** Строго отдельной командой без флага `-l` (например, `tmux send-keys -t s Enter` или `Escape`).
* **Аварийный сброс:** Если в поле ввода оказался не тот текст или сломалась вставка — немедленно слать `tmux send-keys -t s C-u` (очистка строки).

## 3. Машинный контроль прикрепления медиа (Картинки в чат)
Запрещено нажимать Enter, ориентируясь на время. ИИ должен программно убедиться, что интерфейс обработал файл.

1. Скопировать файл в стабильную директорию: `cp /tmp/shot.png /home/voron/Изображения/send.png`
2. Отправить путь как текст: `tmux send-keys -t s -l -- "/home/voron/Изображения/send.png"`
3. Запустить цикл валидации маркера:
```bash
# Ждем превращения текстового пути в токен изображения [Image #N]
for i in {1..10}; do
  if tmux capture-pane -t s -p | tail -3 | grep -q "\[Image #[0-9]\]"; then
    tmux send-keys -t s Enter
    exit 0
  fi
  sleep 0.3
done

# Если маркер не появился — сбрасываем ввод, чтобы не загрязнить контекст модели
tmux send-keys -t s C-u
```

## 4. Чтение экрана без мусора (Фильтрация артефактов TUI)
Интерфейсы на базе `bubbletea` или `ollama` забивают буфер терминала ANSI-последовательностями, псевдографикой и невидимыми пробелами. Прямой парсинг вызовет галлюцинации у ИИ.

```bash
# Полная очистка экрана от управляющих кодов, ANSI-цветов и забиваний (\b)
tmux capture-pane -t s -p -S -50 | sed 's/\x1b\[[0-9;]*m//g' | col -b | sed '/^\$/d'
```

## 5. Динамическое ожидание ответа (Защита от зависаний ИИ)
Запрещено спать фиксированное время (`sleep 25`). В условиях перегрузки реактора или процессора время ответа непредсказуемо. Экран опрашивается каждую секунду на предмет изменения контрольной суммы (хэша) или появления промпта.

```bash
LAST_SHA=""
for i in {1..60}; do  # Максимальный таймаут — 60 секунд
  SCREEN=\$(tmux capture-pane -t s -p | tail -10)
  
  # Условие 1: Появился символ готовности к новому вводу (генерация завершена)
  if echo "\$SCREEN" | grep -q ">>>"; then break; fi
  
  # Условие 2: Текст перестал обновляться (поток токенов иссяк или модель зависла)
  CURRENT_SHA=(echo "SCREEN" | md5sum)
  if [ "\$CURRENT_SHA" = "\(LAST_SHA" ] && [ \)i -gt 5 ]; then break; fi
  
  LAST_SHA=\$CURRENT_SHA
  sleep 1
done
```

## Критические табу (Авто-ликвидация сессии)
1. **Зацикливание генерации:** Если хэш экрана меняется дольше 60 секунд без появления `>>>` — немедленно выполнять `tmux kill-session -t s`. Попытки реанимировать сессию программно запрещены.
2. **Текст вместо токена:** Обнаружен сырой путь к картинке в поле ввода — жать Enter запрещено. Только `C-u` и повтор.
3. **Разрушение сервера:** Команда `exit` внутри запущенного процесса запрещена, так как она может уронить tmux-сервер корабля. Закрытие окон — только через внешнюю команду `tmux kill-session`.
