# Инструмент edit — правила использования

## Главное правило: путь
`path` — любой из: **абсолютный**, **относительный от cwd**, с **«..» за cwd**, с **тильдой**. Всё нормализуется (normalizeToolPath). Несуществующий файл → ошибка, edit не создаёт.

| Что передать | Результат |
|---|---|
| Абсолютный путь (`/tmp/a/t.txt`, даже вне cwd) | ✅ работает (проверено 24.08) |
| Относительный с «..», но после нормализации внутри cwd (`Скрипты_ИИ/../file.md`) | ✅ работает |
| Относительный с «..» за cwd (`../e2e_e2e_escape.txt`) | ✅ работает (E2E 24.08: резолвится в /home/voron/Документы/e2e_e2e_escape.txt) |
| `~/...` или просто `~` | ✅ раскрывается в home-dir (E2E 24.08: `~/.zshrc` → success) |
| Несуществующий файл | ❌ `no such file or directory` — edit НЕ создаёт файлы (только правит существующие) |

## Как строить путь
1. Любая цель — можно сразу абсолютный путь: `/tmp/a/t.txt`, `/home/voron/Документы/...` и т.п. ✅
2. Внутри cwd проще относительный: `/home/voron/Документы/VB-ollama/state.md` → `state.md`.
3. «..» за cwd теперь работает: из VB-ollama `../e2e_e2e_escape.txt` → резолвится в `/home/voron/Документы/e2e_e2e_escape.txt` ✅
4. **read** и **edit** — одинаковая нормализация: тильда + «..» + абсолютные + относительный от cwd.

**Изменено 24.08 (v0.33.0-rc2):** полный путь — абсолютный + «..» за cwd + тильда + относительный от cwd, всё через normalizeToolPath. Старые ограничения «absolute paths are not allowed» и «path escapes working directory» сняты.

## Правила old_text / new_text
- `old_text` должен **точно** совпасть с текстом файла (пробелы, переносы, регистр). Не найдено → `Error: old_text was not found`.
- Совпадение должно быть **уникальным**: если строка повторяется — `Error: old_text matched N times; set replace_all to true`.
- Повторяющееся + заменить все вхождения → тот же edit с `"replace_all": true` (принимает только один edit).
- Несколько разных правок в одном файле → один вызов, массив из N edits. Каждый edit матчится против **ОРИГИНАЛА** файла, не против результата предыдущего. Edits не должны пересекаться; объединяй правки на соседних строках в один edit (включи весь блок).

## Мини-процедура
1. `bash`: убедись, что файл существует и увидишь точный текст для old_text (`cat -n` / `sed -n`).
2. Вызови edit (абсолютный путь или относительный от cwd).
3. При ошибке «not found» — перечитай файл и сверь whitespace; при «matched N times» — либо расширь old_text (включи соседние строки для уникальности), либо `replace_all: true`.

## Self-test (проверка, что ты применил скилл)
Успешный вызов edit вернёт `Updated <path> (N edits, M replacements)`. Если получил ошибку про пути — ты нарушил правило №1, см. таблицу выше.
