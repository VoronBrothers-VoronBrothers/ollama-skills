# Память + самовозобновление (self-restart)

Этот скилл — ЕДИНЫЙ источник правды о том, как сохранить наработки и перезапустить себя, не потеряв знания. Он универсален: работает для любой модели и из любого рабочего каталога.

> **«Чистая модель»** = модель, в Modelfile которой НЕТ знаний о рестарте с памятью. Такие знания она получает ТОЛЬКО из этого скилла. Поэтому всё ниже самодостаточно и использует абсолютные пути.

## Ключевые пути (АБСОЛЮТНЫЕ — не зависят от текущего каталога)
| Что | Путь |
|-----|------|
| Корень проекта | `/home/voron/Документы/VB-ollama` |
| **Память (state)** | `/home/voron/Документы/VB-ollama/Папка заданий для AI/state.md` |
| Задачи | `/home/voron/Документы/VB-ollama/Папка заданий для AI/tasks.md` |
| Лог | `/home/voron/Документы/VB-ollama/Папка заданий для AI/log.md` |
| Скрипт перезапуска | `/home/voron/Документы/VB-ollama/Скрипты_ИИ/restart_self.sh` |
| Boot-скрипт (TUI) | `/home/voron/Документы/VB-ollama/Скрипты_ИИ/ollama_console.sh` |

## Когда использовать
1. **Застрял / зациклился / loop** — нужен выход через новую сессию.
2. **Чекпоинт** — перед долгим/рискованным шагом (чтобы не потерять работу).
3. **Продолжение** — ты новая сессия, продолжаешь предыдущую (сначала читай state.md).

## Процедура

### Шаг 0 — Если ты НОВАЯ сессия (продолжение)
Прочитай `state.md` и `tasks.md` (абсолютные пути выше). Возьми текущую задачу и продолжай с того места, где остановилась предыдущая сессия. **НЕ начинай заново** — состояние уже в state.md.

### Шаг 1 — Память: обнови state.md (ОБЯЗАТЕЛЬНО перед перезапуском)
Напиши в `state.md` актуальное состояние так, чтобы новая сессия (даже «чистая» модель) смогла продолжить без потери контекста:
- **Текущая задача** — что делаем
- **Что уже сделано** (верифицировано) — с доказательствами
- **Что собрано** — файлы, решения, ключевые факты
- **Следующие шаги** — что делать новой сессии
- **Предупреждение для новой сессии** — что НЕ делать (чтобы не зациклиться / не дублировать)

`state.md` — ЕДИНЫЙ источник правды. Если state.md пуст/отсутствует — перезапуск НЕ выполняется (скрипт откажет).

### Шаг 2 — Dry-run (проверка, ничего не меняет)
```bash
DRY_RUN=1 bash /home/voron/Документы/VB-ollama/Скрипты_ИИ/restart_self.sh
```
Скрипт покажет, что бы сделал, но ничего не убьёт. Проверь вывод: state.md найден, затворник OK, boot-путь верный.

### Шаг 3 — Реальный перезапуск (ОБЯЗАТЕЛЬНО ОТДЕЛЁННЫЙ запуск)
```bash
setsid bash /home/voron/Документы/VB-ollama/Скрипты_ИИ/restart_self.sh </dev/null >/tmp/restart.log 2>&1 &
```
**Почему `setsid ... &`:** скрипт убивает свой же TUI; без отделённого запуска он погибнет вместе с ним. Не используй foreground (bash убивает команды через ~180с).

## Что делает restart_self.sh (автоматически)
1. Проверяет, что `state.md` существует и не пуст (иначе **отказ**).
2. Проверяет **затворник от цикла** (`.restart_count`): допускает ТОЛЬКО ОДИН self-restart; 2-й — **отказ**.
3. Ждёт завершения текущего хода (~12с).
4. Убивает **ТОЛЬКО TUI**-процессы ollama (НЕ `ollama serve`, НЕ `llama-server`).
5. Запускает новый TUI через boot-скрипт с промптом «продолжи, прочитай state.md».
6. Помечает перезапуск (`.restart_count` → 2-й будет отклонён).

## Безопасность (жёсткие правила)
- **НЕ убивай** `ollama serve` и `llama-server` (сервер + инференс-бэкенд).
- **НЕ делай** `sudo systemctl restart ollama.service`.
- Затворник `.restart_count` — техническая защита от бесконечного цикла (не зависит от поведения модели).
- `DRY_RUN=1` — безопасная проверка без изменений.

## Верификация (после перезапуска — делает новая сессия)
1. Прочитай `state.md` — убедись, что состояние сохранено.
2. Если state.md говорит «готово / остановись» → допиши строку в `log.md` и **заверши сессию**.
3. Если state.md говорит «продолжай» → продолжай с того места, где остановилась.

## Сброс затворника (только если реально нужен ещё один перезапуск)
```bash
rm /home/voron/Документы/VB-ollama/Папка заданий для AI/.restart_count
```
